# Independent Windows desktop application preview — REAL workflow acceptance

This preview starts the actual **GitHub Community Agent desktop application**
(Tkinter, standard-library UI). It is **NOT** the Nature AI Worker executable.
It is a source-installed developer preview, **not** a signed Windows installer
or final production credential vault. No GitHub writing/posting code is enabled.

## Start on Windows

```powershell
cd C:\Users\aiuser\projects\github-community-agent
git fetch origin
git switch feature/v1-windows-desktop-ui
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\github-community-agent-desktop.exe
```

A **separate native application window** titled
`GitHub Community Agent — V1 Preview (Read Only)` opens. If Python has no
Tkinter/Tcl/Tk installed, the launcher cannot display a GUI; install a
Python distribution including the standard Tcl/Tk components.

## In the real application window

1. Under **Connection settings**, set the public repository
   `nature-ai-corp/nature-ai-worker`. Select `openai`, model
   `gpt-4.1-mini`. Paste your OpenAI API key into the masked in-memory field.
   If running Discussion review or drafting a Discussion reply, paste the
   GitHub Discussions-only READ token into its separate masked field.
   **Never paste keys into screenshots, output files or chat.**
2. Select **Review Issues** and click **Run real workflow**. The application
   makes actual GitHub GET and OpenAI API requests. Verify returned Issue IDs,
   source links, classifications, `read_only:true` and `posted:false`.
3. Select **Review Discussions**. Verify that the app reads the actual
   Discussion #32 announcement, category and contents and reports no invented
   comments. This requires the GitHub token.
4. Select **Draft Replies**, target **issue**, number **33**. Review the
   generated draft (the app does NOT post it).
5. Select **Community Report**. Verify 9 Issue references versus 5 detailed
   records, Discussions coverage, source URLs and partial/unknown counts.
6. After each run use **Export evidence…**, save a unique `.json` file in
   an operator-chosen location. This record is generated by the app itself,
   with UTC start/finish, workflow output and canonical source references.
   Inspect the JSON and compare with live public GitHub sources.
7. Close the app to clear the in-memory credential fields. No credentials are
   persisted in a settings file or JSON export by design. Do not run this
   preview on a shared/untrusted desktop.

## Safety, limitations and honest acceptance status

- This is the **real Windows application UI**, not a CLI test harness. The
  current implementation uses Tk widgets and existing production HTTP
  adapters; there is no demo/mocked mode in the UI.
- While a workflow is running, the UI stays responsive and the Run button
  is disabled. Repeated external actions are not queued or automatic.
- No keys are stored, no GitHub writing and no task scheduling. Saving
  evidence is **explicit**, never automatic.
- Exported files may contain public GitHub text and AI output. They are
  user-reviewed evidence, **not cryptographically signed** or independently
  attested proof. The source code and app build must be identified separately
  for release-grade provenance.
- Only official `openai` and `deepseek` endpoints are exposed in UI;
  arbitrary compatible endpoints are deliberately excluded due to outstanding
  DNS rebinding concerns. There is no local model setup yet.
- First-run UX, credential vault, installer/signing/update/uninstall, Windows
  app identity, accessible UI behavior, robust resilience and durable
  approval-gated GitHub write outbox are **future gates**.
- Native Windows automated tests plus **human-run actual desktop workflows**
  and app-exported evidence must be supplied before app E2E is marked PASS.
